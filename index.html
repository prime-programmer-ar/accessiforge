WCAG 2.1 at a glance — the four POUR principles

P

Perceivable

Information and UI components must be presentable to users in ways they can perceive — text alternatives, captions, contrast, multiple ways to consume content.

O

Operable

UI components and navigation must be usable by everyone — full keyboard support, no traps, enough time, ways to navigate and to reduce motion.

U

Understandable

Content and operation must be understandable — predictable behavior, help with input, clear errors, and a declared page language.

R

Robust

Content must be robust enough to work with current and future assistive technologies — correct names, roles, values and status messages.

Use only the keyboard here. Each card lists what to test and the ARIA it uses. Prefer native HTML; ARIA fills the gaps native elements cannot.

SC 2.1.1 · 2.4.3 · 4.1.2

Tabs

Test: Tab to the module tabs in the header, then use Left, Right, Home and End. ARIA: tablist, tab, tabpanel, aria-selected, aria-controls, roving tabindex.

The five tabs above are the demo — one single Tab stop for the whole bar, arrows moving inside it, automatic activation. Deep links work too: every module has its own URL hash.

Accordion

Test: Enter or Space on a heading button. ARIA: aria-expanded, aria-controls.

The outline that shows where keyboard focus is (SC 2.4.7). AccessiForge draws a 3px focus ring on every interactive element — try tabbing to see it.

Buttons get focus, Enter, Space and a role for free (SC 2.1.1, 4.1.2). A styled <div> gets none of them.

Only one item in a composite widget (like the tabs above) keeps tabindex="0"; the rest are -1. Tab enters and leaves the group once, while arrows move inside it.

Modal dialog

Test: Open it, press Tab (focus stays inside), press Esc (focus returns here). ARIA: native dialog with showModal() supplies the modal role, focus trap and Esc; aria-labelledby and aria-describedby name it.

Confirm

Focus is trapped in this dialog until you close it. Press Esc or choose a button.

Menu button

Test: Enter or Down Arrow opens; Up, Down, Home, End move; Esc closes and returns focus. ARIA: aria-haspopup, aria-expanded, menu, menuitem.

Choosing an item announces it through a status message — no focus jump, no page change.

Toggle switch

Test: Enter or Space toggles; screen readers announce “on/off”. ARIA: role="switch" with aria-checked.

Announced: “Enhanced brewing, off”

Form with validation

Test: Submit empty. Focus moves to the error summary; each link jumps to its field. ARIA: aria-required, aria-invalid, aria-describedby, role=status.

Anything you noticed — flavor, body, roast level.

    POUR · 18 criteria

    How to test

    Keyboard only: Tab, Shift+Tab, Enter, Space, arrows, Esc. Screen readers: NVDA with Firefox or Chrome, VoiceOver with Safari, TalkBack on Android. Also check zoom to 200%, contrast tools, and automated scanners (axe DevTools, Lighthouse, WAVE). Automated tools find only a portion of WCAG issues, so manual testing is required.
